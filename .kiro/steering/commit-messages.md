# Commit Message Guidelines

When completing tasks, always commit your changes with descriptive commit messages that follow these guidelines:

## Commit Message Format

- Start with a concise summary (50 characters or less)
- Use the imperative mood ("Add feature" not "Added feature")
- Include the task reference number when applicable
- Add a more detailed description if needed after a blank line

## Examples

Good commit messages:
```
Add user authentication endpoint
```

```
Fix database connection timeout issue

- Increased connection timeout from 5s to 15s
- Added retry logic for failed connections
- Related to task 2.3
```

## Why Good Commit Messages Matter

- Makes code history more navigable
- Helps team members understand changes without diving into code
- Creates better documentation of the development process
- Simplifies troubleshooting and reverting changes when needed

Always commit your changes with a descriptive commit message at the end of each completed task.
